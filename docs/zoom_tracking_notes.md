# 줌 트래킹 정리 (대화 기록 요약)

작성: 2026-10-23 · 대상: `Mat_Depth_Proj`(Python) + `Unreal/Matte_Zoom`(언리얼)
설계 문서는 [zoom_tracking_design.md](zoom_tracking_design.md), 이 문서는 대화에서 나온 질문·결정·확인 결과를 순서대로 정리한 것이다.

---

## 1. 목표와 문제

- 실제 카메라가 줌을 하면 영상(사람·배경)은 확대되지만 언리얼 CG는 그대로라 어긋난다.
- 거리 추정도 몸 크기로 계산하므로, 줌인을 **사람이 다가온 것으로 오인**한다.
- 그래서 줌 배율을 매 프레임 알아내 **언리얼 카메라 화각**과 **거리 추정 초점거리** 양쪽에 넣어야 한다.

## 2. CV(영상 분석)냐 장비냐

| 방식 | 결론 |
|---|---|
| CV (배경 특징점으로 배율 추정) | 장비 없이 가능하지만, 실제 무대(대형 LED 월, 무빙라이트, 헤이즈, 댄서 다수, 암전)에서는 고정 구조물이 적고 망원일수록 화면이 LED·사람으로 차서 **불안정** |
| 렌즈 엔코더 데이터 | **채택.** 무대 조건과 무관하게 정확 |
| 줌링에 외부 엔코더 부착 | 수동 링 렌즈에만 가능. **박스 렌즈(UA107)는 불가** (줌 기구가 케이스 안, 서보 구동) |

- CV는 오프라인 분석(영상 파일 테스트용 줌 곡선 추정)과 보정 도구로만 사용.

## 3. 사용 장비

| | 렌즈 | 카메라 | 렌즈 데이터 |
|---|---|---|---|
| **실제 현장** | Fujinon **UA107x8.4** 박스 렌즈 (8.4–900 mm, 내장 2배 익스텐더) | Sony **HDC-5500V** (+ HDCU-5500) | 16bit 엔코더 내장, 렌즈 데이터 출력 있음 |
| **테스트** | Canon **HJ14ex4.3B IASE** (4.3–60 mm, 2배 익스텐더) | Sony **HDC-2500** (+ HDCU-2500) | 16bit 엔코더, 가상 스튜디오용 20핀 커넥터 |

두 렌즈 모두 줌 위치를 내보내는 렌즈라 같은 방식(렌즈 데이터 리더)으로 받을 수 있다.

## 4. 줌 데이터를 받는 경로 (조사 결과)

| 경로 | 상태 |
|---|---|
| **렌즈 데이터 리더 → FreeD(랜)** (예: REtracker Fizz II) | 가장 확실. 프로그램 준비 완료. B&H 품절, 유럽 판매처 약 15일, Fujinon 케이블 별도($158). 국내 총판 미확인 |
| **카메라·CCU에서 직접** | **미확인.** Sony 공식 자료에서 CCU 포트가 줌을 직접 출력한다는 내용은 찾지 못함 |
| CCU **TRUNK A** | 카메라↔CCU 사이 **시리얼 데이터 통로**(RS-422/232). 스스로 줌을 내보내지 않음. 카메라 쪽에 시리얼 장비를 연결하면 그 데이터가 실려 옴 |
| CCU **NETWORK TRUNK** (랜) | 카메라↔CCU 사이 **랜 통로**(1Gbps, 광케이블 시스템). 카메라 쪽에 리더를 달면 CCU 쪽 랜으로 받을 수 있어 별도 케이블 불필요 |
| CCU TRACKER (12핀) | 인터컴·탈리용 |
| **SDI 메타데이터** | Sony OCELLUS가 Sony 카메라 SDI에서 줌·포커스·조리개를 읽는 방식이 있음. HDC-5500V가 지원하는지는 Sony 확인 필요. 되면 영상과 같은 프레임에 붙어 와서 지연 보정 불필요 |
| 렌즈 시리얼 직접 (USB-시리얼) | 가능하지만 렌즈 통신 프로토콜 문서 필요 |

- 다른 AI가 "HDC-5500RV는 CCU 랜·버추얼 포트로 줌을 바로 보낸다"고 한 설명은 Sony 한국어 페이지와 대조한 결과 **과장**. 그 페이지 그림에서 트래킹 데이터를 만드는 건 OCELLUS(별도 장비)이고, 네트워크 트렁크는 통로일 뿐이다.

**소니코리아·렌탈사에 확인할 질문**
1. HDC-5500V가 렌즈 줌·포커스를 SDI 메타데이터로 실어 보내는가? 형식은?
2. 그 메타데이터가 CCU(HDCU-5500)의 어느 SDI 출력으로 나오는가? 옵션·펌웨어가 필요한가?
3. CCU의 VIRTUAL·LAN 포트로 렌즈 데이터를 FreeD 등으로 직접 출력할 수 있는가?
4. 테스트용 HDC-2500 + HDCU-2500에서도 되는가? TRUNK A 핀 배치와 통신 설정은?

**추천 순서**: Sony 문의 + 리더 견적 동시 진행 → 테스트 날 CCU 포트(SDI·랜·시리얼)를 기록 도구로 직접 확인 → 안 되면 Fizz II 구매·렌탈.

## 5. 전체 구조 (구현 완료)

```
렌즈 ─(리더/CCU)─▶ [Python rvm_main] 줌 소스 → 지연 보정 → 렌즈 테이블 → 배율
                     ├─ 거리 추정 초점거리 = 와이드 초점거리 × 배율
                     └─ 누끼 영상 왼쪽 위 숨김 코드 블록 5 (배율)
                          ▼ Spout (RVM_OUTPUT)
               [언리얼 BP_ZoomCamera] 매 프레임 코드 읽기 → 화각 변경 → 판 크기 맞춤
```

- 줌 값이 **영상 프레임 안에** 실려 가서 언리얼에서 영상과 CG가 같은 프레임에 맞는다. 이게 Python에서 받는 핵심 이유다.
- 언리얼에서 직접 받는 방법(LiveLink FreeD)도 있지만, 영상과 줌이 따로 도착하고 Python 거리 추정이 줌을 모르게 되므로 채택하지 않았다.

### 숨김 코드 (누끼 영상 왼쪽 위, 알파 0)

| 블록 | x 픽셀 | 내용 |
|---|---|---|
| 0 | 0–3 | 사람 거리 mm |
| 1 | 4–7 | 서명 (초록) |
| 2–4 | 8–19 | 로고 연출 (Matt_test용) |
| 5 | 20–23 | **줌 배율** `ln(s)/ln(256)`, B=255 유효 |
| 6–7 | 24–31 | 예약 |

### Python (`Mat_Depth_Proj`)

| 파일 | 역할 |
|---|---|
| `module/engine/zoom/` | 교체 가능한 줌 소스: `freed`(FreeD UDP), `manual`(키보드), `replay`(프레임별 CSV). 새 장비는 소스 하나만 추가 |
| `lens/UA107x8.4_placeholder.json` | 렌즈 테이블 (**임시값**, 실측 보정 필요) |
| `tools/freed_sim.py` | FreeD 시뮬레이터 |
| `tools/estimate_zoom_offline.py` | 영상 파일 줌 곡선 추정 (CV, replay용) |
| `tools/zoom_spout_test.py` | RVM 없이 언리얼 확인용 합성 영상 + 줌 코드 송출 |
| `tools/test_zoom_source.py` | 오프라인 테스트 |
| `run_zoom_file_test.cmd` | 영상 파일 + replay로 전체 경로 테스트 |

실행 옵션: `--zoom-source off|freed|manual|replay`, `--zoom-lens`, `--zoom-delay-ms`, `--zoom-extender`, `--freed-port 40000`, `--freed-camera-id`
실행 중 키(Python 프리뷰·cmd 창): `[` `]` 지연 ∓5 ms, `X` 익스텐더, `=` `-` `Z` 수동 줌

### 언리얼 (`Unreal/Matte_Zoom`)

- C++ 플러그인 **ZoomTracking** (`AZoomCameraActor`) → 블루프린트 **BP_ZoomCamera**
  - 숨김 코드(블록 0·1·5) 읽기 → 초점거리 = `WideFocalLength` × 배율
  - 태그 `ZoomPlate` 판을 화각에 맞춰 화면 꽉 채움, 태그 `PersonPlate` 판을 사람 거리로 이동
- 레벨 `Zoom_Stage`: 카메라(UA107 와이드 8.4 mm, 59.4°), 배경 판 100 m, 사람 판, 테스트 기둥, Spout 수신(`BP_SpoutInputs`)
- 장면 단위는 실제 cm
- 설정 스크립트: `Tools/setup_zoom_stage.py`

## 6. 테스트 결과

| 테스트 | 결과 |
|---|---|
| 합성 줌 영상 (x1–x20) | CG 마커가 배경 표시 안에 유지됨 |
| FreeD 시뮬레이터 → Python | 수신·지연 보정 정상 (오차 0.1%) |
| 블록 5 왕복 정밀도 | 0.005% 이하 |
| 하츠하 59.94p 클립 (replay) | 언리얼이 x1.1–1.56 줌을 따라감 |
| 숨김 코드 읽기 비용 | 약 4–8 ms/프레임 (동기 읽기) |
| 실제 렌즈·장비 | **아직 미테스트** |

## 7. 영상 파일로 테스트

- 녹화 영상에는 줌 값이 없으므로 `estimate_zoom_offline.py`로 줌 곡선을 미리 추정하고 `--zoom-source replay`로 프레임 번호에 맞춰 재생한다.
- **OBS로 재생하면 프레임 번호를 알 수 없어 replay 줌이 맞지 않는다.** 파일 입력(`--ffmpeg-in file`)을 써야 한다.
- 테스트 영상 탐색: 큰 무대 + 완전 고정 카메라 + 걸어나오는 샷은 유튜브에서 찾기 어려웠다. 오드아이써클 인기가요 풀캠(2:30–2:45, 고정 후 줌인)을 사용했고, 결론적으로 **직접 촬영을 추천**(실제 렌즈 특성·카메라 높이까지 확보).

## 8. 렌즈를 바꿀 때 설정할 값

| 항목 | HJ14ex4.3B (테스트) | UA107x8.4 (실제) |
|---|---|---|
| 렌즈 테이블 `--zoom-lens` | 새로 작성 필요 | 실측 보정 필요 |
| 언리얼 `ZoomCamera` → `Wide Focal Length` | 4.3 | 8.4 |
| Python `--dist-hfov` (와이드 화각) | 약 96 | 약 59.4 |

- 두 곳을 따로 바꿔야 해서 실수 위험이 있다. 개선안: Python이 배율 대신 **실제 초점거리(mm)**를 보내 렌즈 파일만 바꾸면 되게 하기 (미적용).

## 9. 현장 보정 절차 (장비 연결 후)

1. 리더/CCU 출력을 PC로 연결 (랜이면 같은 대역 고정 IP, 포트 40000, 방화벽 허용)
2. Python 로그에 `zoom=x..`가 나오는지, 렌즈를 돌리면 바뀌는지 확인 (`zoom=-`면 데이터 없음)
3. 렌즈 테이블: 와이드·중간·텔레에서 "엔코더 값 → 실제 배율"을 기록해 JSON에 넣기
4. 지연: 빠르게 줌하며 CG와 영상이 어긋나지 않을 때까지 `[` `]`로 맞추고 `--zoom-delay-ms`에 고정
5. 익스텐더 상태가 오는지 확인 (안 오면 `X` 키)
6. 언리얼: Play 중 `ZoomCamera` → Zoom|Status의 `Current Scale`, `Code Valid`, 출력 로그 `LogZoomCamera ... code=ok`

## 10. 영상 입력 (DeckLink)

- `--dshow-name "Decklink Video Capture"`: DeckLink의 DirectShow 장치. 영상만 들어오고 **SDI 메타데이터는 못 받는다.**
- `--ffmpeg-in decklink` (직접): 지연이 조금 짧고, 나중에 SDI 메타데이터 줌을 받으려면 이 경로가 필요.
  - 데크링크 지원 ffmpeg: `D:\FFmpeg000\ffmpeg.exe` (없던 `libiconv-2.dll`을 Git 폴더에서 복사해 해결)
  - 장치 `DeckLink 4K Extreme 12G`, 카메라 신호는 **1080p59.94 → `Hp59`**
  - 59.94 전체 처리는 GPU가 못 따라가서(약 40 fps) `--target-fps 30000/1001`로 처리
  - 지연이 쌓이던 문제 수정: ffmpeg DeckLink 대기열을 4프레임으로 제한, 처리 FPS가 낮으면 ffmpeg에서 미리 프레임을 줄임
- SDI 메타데이터로 줌을 받으려면: ① 카메라가 실어 보내는지 확인 → ② 데크링크 SDK 기반 입력부 제작 (ffmpeg는 타임코드·자막·KLV만 꺼냄)

## 11. 줌과 함께 다룬 관련 작업

- **사람 판 깊이 + 통과 오브젝트**: 사람 판을 거리만큼 이동, 테스트 기둥(540 cm) 배치
- **거리 추정 개선**: 어깨 폭 대신 어깨–골반–무릎–발목 세로 길이 기본 (`--dist-body full`), 흔들림 8.6% → 1.5%
- **운영자 키 (언리얼)**: `F` 앞(400 cm) / `G` 뒤(700 cm) / `A` 자동, 1.5초 부드럽게 이동, 기둥이 사람 부분만 디졸브(스르르 통과)
- **줌 오인 버그 수정**: 줌 소스가 없을 때 무대 색이 블록 5로 읽혀 화각이 튀던 문제 → 코드 줄을 먼저 비우고 쓰도록 수정
- **화질**: 언리얼에서 영상이 TSR·톤매퍼·화면 해상도 축소를 거쳐 선명도 약 40%로 떨어짐
  - Matte_Zoom: 톤매핑 뒤 원본 픽셀 합성 방식이 복사본에서 픽셀 단위 일치 확인 (실제 프로젝트 미적용)
  - Matte_2P_v2: 안티에일리어싱 끔, 화면 해상도 100%, 카메라 후처리 정리, 정확한 sRGB 변환 적용 완료
  - Python 누끼 색을 RVM 예측색 대신 **원본 픽셀**로 전송 (`--matte-color source`, 기본)
